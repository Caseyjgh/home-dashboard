# Google OAuth configuration

The project uses **NextAuth/Auth.js 5.0.0-beta.32**, the Google OAuth/OIDC provider, and JWT sessions. The provider and Calendar token-refresh code continue using the original server-only names:

- `CLIENT_ID`: existing Google Web OAuth client ID
- `SECRET`: existing Google client secret
- `AUTH_SECRET`: existing session signing/encryption secret
- `AUTH_URL`: optional canonical public origin, explicitly set for Pi Preview

No `NEXT_PUBLIC_*`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, or `AUTH_GOOGLE_*` variables are needed. Auth.js normally recognizes additional conventional names, but this application's validator requires the established names above, including AUTH_SECRET because Calendar JWT decoding uses it directly. `NEXTAUTH_URL` is supported as an older canonical URL alias; if both URL variables exist they must agree. `NEXTAUTH_SECRET` is not a substitute for AUTH_SECRET here.

## Confirmed cause and repair (2026-09-14)

`src/auth.ts` was identical on `pi5` and the Pi redesign branch. Vercel's `CLIENT_ID` and `SECRET` were scoped only to Production, so the Preview provider received undefined credentials. `AUTH_SECRET` was already shared. The existing two credential records were updated to include Preview without reading/replacing their values. No new Google client or secret was created.

The Pi branch's `AUTH_URL` is now:

```
https://home-dashboard-git-pi5-vercel-kc-e777.vercel.app
```

Google Cloud Console → Google Auth Platform → Clients → the **existing Web application client** → Authorized redirect URIs → add the exact URI below if missing, then Save:

```
https://home-dashboard-git-pi5-vercel-kc-e777.vercel.app/api/auth/callback/google
```

Retain the original production redirect URI. The current Vercel production domain assignment is `home-dashboard-umber.vercel.app` (not the older `lumber` spelling in the original README):

```
https://home-dashboard-umber.vercel.app/api/auth/callback/google
```

Pi and production use the same OAuth client but separate host-scoped cookies. Pointing Pi AUTH_URL at the original production app would complete login there rather than on Pi. Use the stable Pi branch alias, or a dedicated Pi custom domain assigned to that branch, rather than a temporary commit deployment URL. If a custom Pi domain is assigned later, update only its branch-scoped AUTH_URL, Google redirect URI and kiosk URL, then redeploy.

When AUTH_URL is absent on Vercel, the code uses `VERCEL_BRANCH_URL` for Preview or `VERCEL_PROJECT_PRODUCTION_URL` for Production. It never uses ephemeral `VERCEL_URL`. Local development uses the request origin, for example `http://localhost:3000/api/auth/callback/google`. No auth redirect proxy is configured.

## Validation and diagnostics

Next config and the server auth module reject missing/blank credentials, surrounding whitespace/quotes, an invalid client-ID shape, conflicting URL aliases, and localhost on Vercel. They never substitute blank strings or log secrets. Missing local credentials intentionally stop `npm run build`/`npm run dev`; supply the existing credentials through `.env.local`, which remains ignored by Git.

Build/start logs and `GET /api/auth/config` report only variable names, presence booleans, the final six client-ID characters, canonical origin, and callback URL. The response is uncached and contains no full credential or secret. `GET /api/auth/providers` shows the callback generated by Auth.js itself. Syntax validation cannot prove a Google client still exists: the deployed provider initialization and consent redirect must also be checked.

The original scopes remain `openid email profile https://www.googleapis.com/auth/calendar.readonly`. Calendar cache/refresh behavior and dashboard features are unchanged. Vercel Preview protection still applies; this change does not weaken it. Google Cloud credential settings cannot be edited through the available Vercel access.
